# MicMonitor 仕様書 v0.5

マイク入力をリアルタイムでモニタリングするアプリ。macOS・iOS・iPadOS（visionOS もビルドは通る）。用途は自分用（デバッグ実行）。

## 1. 要件

### 1.1 機能要件

| # | 機能 | 内容 |
|---|------|------|
| F1 | マイク選択 | 接続中の入力デバイスを一覧表示して選択。先頭に「システム既定」 |
| F2 | レベル表示 | チャンネルごとのレベルメーター（Peak + RMS、dBFS） |
| F3 | 波形履歴 | チャンネルごとに直近 N 秒分の波形（縦軸 dB スケール）をスクロール表示 |
| F4 | 設定 | N（1〜60 秒、既定 10 秒）とスペクトログラムのカラーマップを設定画面（macOS は設定ウィンドウ（⌘,）、iOS はシート）で変更。カラーマップは選んだものの見本・色の流れ・特徴を表示する |
| F5 | モニター再生 | 入力音を出力デバイス（macOS はシステム既定の出力、iOS はそのときの出力先）で再生。オン/オフと音量 |
| F6 | 入力音量 | 選択中デバイスの入力音量を表示・変更（macOS はシステム設定 > サウンド > 入力 と同じ値、iOS はオーディオセッションの入力ゲイン。5.1 節） |
| F7 | カード表示 | macOS のみ。画面の最前面に常駐する小さなカード（メーター・波形・スペクトルまたはスペクトログラム・入力音量）。ウィンドウ表示と切り替え |
| F8 | スペクトル | 入力の周波数スペクトル。ウィンドウ表示は波形の下、カード表示はメーターの下 |
| F9 | 計測の停止 | 計測（マイク入力）を止めて、マイクの使用をやめる。ボタンで再開 |
| F10 | スペクトログラム | スペクトルの直近 N 秒の履歴を濃淡で表示（横軸が時間、縦軸が対数周波数）。ウィンドウ表示は波形とスペクトルの間。カード表示はスペクトルの欄をクリックしてスペクトルと切り替える（選択は保存）。時間軸は波形とそろえる |

### 1.2 決定事項

- 対象: macOS 27.0 以降、iOS・iPadOS・visionOS 27.0 以降（1 つのマルチプラットフォームのターゲット）。Swift 6 言語モード、Default Actor Isolation は指定なし（nonisolated）
  - 音声層の違いは 3.3 節、画面の違いは 6.2 節。カード表示（6.1 節）は macOS のみ
- メーター: 表示レンジ -60〜0 dBFS、Peak（淡色）と RMS（濃色）、ピークホールド 1.5 秒、クリップ表示（-0.1 dBFS 以上で点灯し、最後のクリップからピークホールドと同じ 1.5 秒で自動的に消える。クリックですぐに消せる）
- 波形: チャンネルごとに 1 段。符号付き表示（上側が正、下側が負）。縦軸は各側とも dB スケール（中心が -60 dBFS 以下、端が 0 dBFS）
- スペクトル: FFT（Hann 窓、48 kHz で 4096 点 ≈ 11.7 Hz・85 ms。64 kHz を超えるときは 8192 点）。全チャンネルのパワーを平均した 1 本。横軸は対数で 20 Hz〜20.48 kHz を 1/12 オクターブの帯域に分け、帯域内のビンの最大値を表示（ビンより狭い低域は補間）。縦軸 -100〜0 dBFS（フルスケールの正弦波が 0 dB）。塗りが現在値（減衰 60 dB/s）、線がピークホールド（1.5 秒保持後 30 dB/s で下がる）
- スペクトログラム: 20 ms ごと（50 列/秒）にスペクトル表示と同じ FFT と帯域分け（1/12 オクターブ × 120 帯域）を行い、-100〜0 dBFS を 0〜255 に量子化して保持（60 秒で 360 KB）。全チャンネルの平均。描画はレベルを色に変えた画像を作って貼る。色の付け方（カラーマップ）は設定で選ぶ: 単色（アクセントカラーの濃さ。レベルに比例したアルファ、既定）、または知覚的に均一な viridis・magma・inferno・plasma（matplotlib の 256 色の表をそのまま埋め込み、不透明で塗る。いずれも CC0）。1 ピクセルに複数列が入るときは最大値を取り、まとめ方は波形と同じく通し番号で固定する。まとめ方が固定なので届き終わった列のピクセルは変わらない。画像は使い回し、新しい列が届いたら画素を左にずらして最新の列を含むピクセルだけを描き足す（列が増えていないフレームは前の画像のまま。まとめる列の数・容量・カラーマップ・アクセントカラーが変わったら作り直す）。スナップショットの比較は通し番号・容量・列数だけで行う（SwiftUI がビューの入力を毎フレーム比べるため、レベルの配列を要素ごとに比べさせない）。計測を止めている間は止めた時点のまま表示する
- 表示モード（macOS）: 通常ウィンドウ 1 枚（`Window` シーン）と、最前面のカード（6.1 節）を切り替える。ウィンドウ表示でウィンドウを閉じたらアプリ終了。iOS は画面 1 つ（6.2 節）
- 文字の大きさ: text style（`AppFont`）で指定し、iOS では Dynamic Type に従う。macOS の text style は大きさが固定で、docs/ui の Mac の寸法と同じになるものを選ぶ。Mac 専用のカード（6.1 節）だけは固定の大きさ
- 入力デバイスの一覧からはプライベートな集約デバイス（AVAudioEngine が既定の入出力を束ねるために自動で作る `CADefaultDeviceAggregate-<pid>-<n>`）を除く。判定はトランスポートの種類が集約で、構成に `kAudioAggregateDeviceIsPrivateKey` があるもの。ユーザーが作った集約デバイスは残す
- 「システム既定」選択時は OS 側の既定マイク変更に追従
- 選択中のデバイスが外れたらシステム既定で継続し、再接続されたら元のデバイスに戻す
- 次の設定は UserDefaults に保存する（保存先はすべて UserDefaults で、ファイルやデータベースは使わない）
  - `MonitorModel`: 選択デバイス（UID と、未接続のときに表示する名前）・N・モニター再生のオン/オフと音量
  - `DisplayModeController`（macOS）: 表示モード（6.1 節）、カードの位置と幅（`setFrameAutosaveName`）
  - `@AppStorage`: カードの各セクションの表示（6.1 節、macOS）、スペクトログラムのカラーマップ
- 対象外: 録音・保存
- 配布: 自分用。署名・公証は考慮しない

## 2. 技術選定

| 領域 | 採用 | 理由 |
|------|------|------|
| UI | SwiftUI。macOS は `Window` + `Settings` シーン、iOS は `WindowGroup`（ウィンドウは 1 つ）と設定のシート | |
| 状態管理 | Observation (`@Observable`, `@MainActor`) | |
| デバイス一覧・変更通知 | macOS: Core Audio HAL (`AudioObject*`)。iOS: `AVAudioSession` の入力ポートと経路の変更通知 | macOS: 入力ch数・UID の取得、追加/削除・既定デバイス変更の監視ができる。iOS には HAL がない |
| 音声入出力 | AVAudioEngine。入力デバイスは macOS では `inputNode` の `setDeviceID(_:)`、iOS ではセッションの `setPreferredInput(_:)` で指定し、`AVAudioSinkNode` で受け取る | `installTap` は macOS では 100 ms（4800 フレーム）単位でしか届かず、表示が 10 Hz になる。シンクノードは I/O の処理単位（macOS は 512 フレーム ≈ 10.7 ms）で呼ばれる |
| 信号処理 | Accelerate (vDSP) | |
| 描画 | SwiftUI `Canvas` + `TimelineView(.animation)` | |
| スレッド間共有 | `Synchronization.Mutex` | |

AVAudioEngine でデバイス切り替えが不安定な場合は、AUHAL を直接使う実装に差し替える（`AudioCaptureEngine` の中だけで閉じるようにしてある）。

| `TimingProbe` | DEBUG ビルドのみの計測用。ポンプの処理間隔と描画フレームの間隔を記録し、計測開始後のログに統計を出す | Sendable + Mutex |

### 3.1 スレッドの方針

- シンクノードのクロージャはリアルタイムスレッドで呼ばれる。ここではリングバッファへのコピーだけを行い、ロック・メモリ確保・MainActor への hop をしない。
- Mutex を使う集計と再生の予約は、ポンプのタスクで行う。ポンプの間隔ぶん（最大 5 ms 程度）の遅れが加わる。
- リングバッファがあふれたら（ポンプが 1 秒以上止まった場合）そのブロックを捨てて数える。
- シンクのクロージャは `nonisolated` な関数の中で生成する（MainActor のコンテキストで作ると、Swift 6 の実行時の分離チェックでクラッシュするため）。
- `MonitorPlayback` は解放がメインスレッド以外で起きると AVAudioEngine 内部でデッドロックしてクラッシュするため、`@MainActor` のクラスにして `isolated deinit` を持たせる。ポンプのタスクは停止後も次の周期（最大 5 ms）まで参照を持つが、最後の参照がどのスレッドで手放されても解放は MainActor で行われる。
- 実測（MacBook Air 内蔵マイク、48 kHz）: シンクノード 94 回/秒（512 フレーム）、あふれ 0、描画 60 fps。
- UI は毎フレーム、ストアからスナップショットを取得して描画する（プル型）。

### 3.2 エンジンの再構成

次の場合にエンジンを作り直す（数十 ms 途切れる）。

- 解決したデバイスの ID が変わった（選択変更、デバイスの抜き差し、既定デバイスの変更）
- モニター再生のオン/オフ（オフのときは出力側に一切接続しない）
- `AVAudioEngineConfigurationChange` 通知（サンプルレート変更など。`NotificationCenter.notifications(named:object:)` を MainActor のタスクで受け取る）。300 ms 待ってから作り直す
  - この通知は起動直後にも届くため、エンジンが止まっているか、入力フォーマットが変わったときだけ作り直す（毎回作り直すと再起動のループになる）

- iOS: 経路の変更（`routeChangeNotification`）で使うデバイスが変わったとき、メディアサービスの再起動（`mediaServicesWereResetNotification`）のとき

ch 数が変わらなければ波形履歴は保持する。スペクトログラムの履歴は全チャンネルの平均なので、ch 数やサンプルレートが変わっても保持する。

### 3.3 プラットフォームごとの実装

OS に依存する部分は `MicMonitor/Audio/AudioPlatform.swift` のプロトコルにまとめ、実装を同じ型名で `Platform/macOS/` と `Platform/iOS/` に置く（iOS 用は visionOS でも使う）。ビルド設定 `EXCLUDED_SOURCE_FILE_NAMES[sdk=…]` でもう一方を除外するので、コンパイルされるのはどちらか一方だけ。

| プロトコル | 実装 | macOS | iOS |
|------|------|------|------|
| `InputDeviceSource` | `PlatformInputDevices` | HAL のデバイス一覧と既定の入力デバイス。プライベートな集約デバイスを除く | `availableInputs`。既定は優先する入力を指定していないときの経路の入力（指定中は最後に見たもの、なければ内蔵マイク） |
| `InputVolumeBackend` | `PlatformInputVolume` | HAL の入力音量とミュート（5.1 節） | `inputGain`（経路によっては変更できない）と、`AVAudioApplication` の入力ミュート |
| `AudioSessionControlling` | `AudioSessionController` | 何もしない。入力デバイスはエンジンの入力ノードに `setDeviceID(_:)` で指定する | 下記 |

iOS のオーディオセッション:

- エンジンを作る前に有効にする（`MonitorModel.restart()`）。カテゴリはモニター再生がオフなら `.record`、オンなら `.playAndRecord`（`.allowBluetoothA2DP`）。どちらも `.allowBluetoothHFP` で、モードは `.measurement`（自動ゲインや音声処理を切る）。ハウリングを避けるため、スピーカーに切り替える指定（`.defaultToSpeaker`）はしない（ヘッドホンがないときの出力先は OS が決める。実機では未確認）。
- 入力の処理単位は 10 ms を希望する（`setPreferredIOBufferDuration`。実際の値は経路で決まる。iOS 27 シミュレータでは 5.3 ms（48 kHz で 256 フレーム）になった）。
- 入力の一覧はカテゴリを設定してから取れるため、有効にしたあとで一覧を取り直してから使うデバイスを決める。
- 計測を止めたら無効にする（`.notifyOthersOnDeactivation`）。
- セッションの設定と有効化・無効化は終わるまで呼んだスレッドを止めるので、メインスレッドの外（`@concurrent` の関数）で同期の `setActive` を呼ぶ。メインスレッドで呼ぶと Xcode が UI の応答が止まると警告する。非同期の `activate(options:)` は使わない（完了してすぐにエンジンを作ると入力のフォーマットがまだ 0 Hz で、I/O ユニットの初期化に失敗した。iOS 27 シミュレータ）。
- 有効化を待つ間に別の再構成・停止・割り込みが起きうるため、`MonitorModel` はセッションの操作を 1 つずつ順に行い、再構成ごとの世代番号で古い再構成ではエンジンを始めない。
- 割り込み（通話・Siri など）: `didBecomeInactive` メッセージ（`.systemInterruption`）で計測を中断し、「通話などの割り込みのため、計測を中断しています。」と表示する。中断中は再構成しない。`resumptionRecommendation` メッセージで再開がすすめられたら再開し、すすめられなければ計測を止めた状態（6 章）にする。
- モニター再生を別のエンジンにする理由（5 章）は macOS のものだが、iOS でも同じ構成のまま使う。

## 4. 信号処理

### 4.1 レベル

- ポンプが読み出したブロック（macOS では通常 512 フレーム）ごとに、ch ごとに `vDSP_maxmgv`（Peak）と `vDSP_rmsqv`（RMS）を計算する。
- Peak は UI が読むまで最大値を保持し、読んだらリセットする（取りこぼしを防ぐため）。
- 表示側: アタックは即時、リリースは 20 dB/秒、ピークホールドは 1.5 秒保持してから 20 dB/秒で下げる。
- 色分け: 緑（〜-18 dB）、黄（〜-6 dB）、赤（-6 dB〜）。

### 4.2 波形履歴

- 200 ビン/秒（5 ms/ビン）に間引く。1 ビン = 最大値（`vDSP_maxv`）、最小値（`vDSP_minv`）、RMS（`vDSP_svesq` の合計から計算）。符号を残すので、非対称な波形・DC オフセット・片側だけのクリップが見える。
- バッファ境界をまたぐビンは累積値を持ち越して計算する。
- 容量 = N × 200（60 秒 × 2ch でも約 290KB）。N を変えたら、最新のものから入る分だけ引き継ぐ。
- 描画: 1 ピクセル以上の幅になるようにビンを数個ずつ列にまとめ、各列の最大値・最小値・RMS をまとめ、上側に正の最大値、下側に負の最小値の大きさを、それぞれ dB → 0〜1 に正規化して描く（淡色）。RMS は符号を持たないため上下同じ高さで重ねる（濃色）が、各側の振れ幅は超えないようにする。
- 列のまとめ方は表示位置ではなく、ビンの通し番号（記録開始からの累計）で固定する。表示位置で区切ると、データが届くたびに列の中身が入れ替わり、片側だけのビン（5 ms の中で符号が変わらないもの。実測で約 1 割）が出たり消えたりしてチラつく。

## 5. モニター再生

- macOS の AVAudioEngine は inputNode と outputNode で 1 つの I/O ユニットを共有する。入力デバイスを指定したエンジンの出力はそのデバイス（入力専用なら 0 ch）になり、別デバイスへの出力は初期化に失敗する（-10875）。
- そのため再生は**出力専用の別エンジン**（`MonitorPlayback`）で行う。ポンプから受け取ったバッファをコピーし、`AVAudioPlayerNode.scheduleBuffer` で予約する。出力先はシステム既定の出力デバイス（iOS はオーディオセッションのそのときの出力先）で、サンプルレートの違いは mainMixer が変換する。
- 再生待ちが 250 ms を超えたら入力を捨て、クロック差で遅延が増え続けないようにする。遅延は入力の処理単位（約 11 ms）、ポンプの間隔（最大 5 ms）、出力側のバッファの合計。
- 再生の開始に失敗しても計測は続け、モニター操作の下にエラーを表示する。
- 再生側のエンジンが止まったら（出力デバイスの変更など）全体を再構成する。
- 既定はオフ。ハウリング防止のため、UI にヘッドホン使用の注意を出す。
- 入力が 3ch 以上のデバイスでは無効にする（ミキサーのチャンネルレイアウトが合わずに例外で落ちるのを避けるため）。必要になったら ch 選択式で対応する。
- 入力と出力が別デバイスのため、クロックのずれによる途切れは許容する。

## 5.1 入力音量

- Core Audio HAL の `kAudioDevicePropertyVolumeScalar`（入力スコープ、0...1）を読み書きする。システム全体の設定なので、アプリを終了しても値は残る。
- 要素 0（マスター）があればそれを使い、なければ音量を持つチャンネル（要素 1...n）すべてに同じ値を設定する。表示はその平均。
- `AudioObjectIsPropertySettable` で変更できないデバイスはスライダーを無効にし、理由を表示する。
- 音量プロパティを監視し、システム設定や他のアプリでの変更を UI に反映する。対象デバイスが変わったらリスナーを付け替える。
- スライダーは無段階。7 つの目盛り（0%, 17%, 33%, 50%, 67%, 83%, 100%）を表示し、目盛りから ±2% 以内では目盛りの値に吸着する。
- iOS では、音量はオーディオセッションの入力ゲイン（`inputGain`、0...1）。経路によっては変更できない（`isInputGainSettable`）。ミュートは `AVAudioApplication` の入力ミュートで、このアプリの入力だけが無音になる（iOS にはシステム全体の入力ミュートがない）。ゲインを変更できない経路でもミュートはできる。
- ミュートボタンは、デバイスがミュートを持つか音量を変更できれば使える。
- 入力音量は多くのデバイスでゲインであり、0 は無音ではない（実測: MacBook Air 内蔵マイクは scalar 0...1 が -12...+12 dB。0 でもピーク -30 dB 程度の音が入る）。
- そのため、デバイスがミュート（`kAudioDevicePropertyMute`、入力スコープ、変更可能）を持つ場合は、スライダーの 0 をミュートとして扱う。0 にすると音量 0 + ミュート、0 より上に戻すとミュートを解除する。マスター（要素 0）にミュートがあればそれを使い、なければ音量と同じ要素を使う。
- スライダー横のマイクボタンでミュートと解除を切り替える。
  - ミュート: 音量はそのまま残し、ミュートだけをオンにする。ミュートを持たないデバイスでは音量を 0（最小ゲイン）にし、それをミュート扱いにする。
  - 解除: ミュートをオフにする。音量自体が 0 のとき（スライダーで 0 にしてミュートした場合など）は、ミュート前の音量に戻す。ミュート前の音量は、ボタンでミュートしたときはその時点の音量、スライダーで 0 にしたときはドラッグを始めたときの音量。わからなければ 50%。
- ミュート中はスライダーを 0、マイクボタンを赤い `mic.slash` で表示する。システム設定や他のアプリでのミュートも監視して反映する。ミュートを持たないデバイスでは、0 は最小ゲインのまま。

## 6. UI

- 見た目（色・寸法・文字の大きさ）は docs/ui の画面デザイン（iOS は docs/ui/ios）に従う。独自の色（グラフの下地、波形の RMS、ピークホールド線など）は Asset Catalog にダーク・ライトの 2 値で登録し、アクセントはシステムのアクセントカラーを使う。
- Mac のウィンドウ（上から）: 「入力」ラベル付きのデバイスピッカーとフォーマット表示（例: 48 kHz · 2 ch）。フォールバック中はその下に警告色で「『○○』が接続されていないため、システム既定で継続中」。右上に計測の停止ボタンと「カード表示」ボタン。入力音量スライダー（右端に割合）。その下の各欄は見出し（左に名前、右に説明）付きの枠で囲む: レベル（ch ごと: ラベル、バー、「CLIP」、数値＝ピークホールドの dB の順。目盛りは -60/-48/-36/-24/-18/-12/-6/-3/0）、波形（ch ごと）と時間軸、スペクトログラムと時間軸、スペクトル（dB 軸は 20 dB ごと、周波数軸は 20〜20k、縦の格子線は 100/1k/10k）。最下段に区切り線とモニター再生の操作（スイッチ、音量スライダーと割合、ヘッドホンでの視聴の注意）。
- 時間軸の目盛りは右端が now。間隔は 1・2・5・10・15・20・30 秒のうち、N 秒を 5 つ以下に分ける最小のもの（N = 10 なら 2 秒ごと）。
- 横軸の目盛りの文字（時間・dB・周波数）は、幅が足りなければ重ならないように間引く。右端（now・0 dB・20k）から 1 つおき・2 つおき…と同じ数ずつ飛ばして残し、左端は重ならなければ残す（`AxisLabels`）。
- 計測の各欄の寸法（グラフの高さ・余白・角丸・列の幅）は `MonitorMetrics` にまとめ、画面ごとに環境値で渡す。チャンネル番号と目盛りの列の幅は Dynamic Type の倍率を掛け、グラフの欄の文字は `accessibility1` までで止める（グラフの領域を残すため）。
- マイク権限が拒否されている場合は、システム設定（iOS は設定アプリのこのアプリの欄）を開くボタンを出す。アプリが前面に戻るたびに権限を確かめ直し、許可されていれば計測を始める。
- 計測の停止・再開: Mac のウィンドウは右上（「カード表示」ボタンの左）、カードはヘッダーの左端のボタン、表示メニューの「計測を停止 / 計測を開始」（⌘.）。iOS は 6.2 節。
  - 名前は「計測」とする（入力をヘッドホンに流す「モニター再生」と区別する）。アイコンは一時停止・再生（`pause.fill` / `play.fill`）で、入力音量の横のマイクのボタン（入力ミュート。macOS ではシステム全体で他のアプリの録音にも効き、iOS ではこのアプリだけ）と区別する。
  - 止めるとオーディオエンジンを解放するので、マイクの使用（メニューバーのマイク使用中の表示）も止まる。モニター再生も止まる。
  - 止めている間はメーターとスペクトルの代わりに「計測を停止中」と表示し、波形とスペクトログラムは止めた時点のまま表示する（ウィンドウ表示では見出しに「停止時点のまま表示」）。ウィンドウ表示の「計測を開始」ボタンは主ボタン（アクセントカラー）にする。カード表示では、スペクトルの欄がスペクトログラムのときだけ表示し、止めている間はスペクトルとの切り替えはできない。
  - 止めている間は、ウィンドウやカードが表示されたとき（`start()` が呼ばれる）や、デバイスの抜き差し・モニター再生の切り替えでも再開しない。状態は保存せず、次回の起動時は計測を始める。
- 設定（macOS は ⌘, の設定ウィンドウ。iOS の違いは 6.2 節）: 「波形」の節に履歴の長さ N（スライダー + ステッパー、1〜60 秒。波形とスペクトログラムの両方に効く）、「スペクトログラム」の節にカラーマップの選択（各行に色の見本の帯が付いたラジオの一覧）と、選んだものの見本（計算で作った話し声のようなスペクトログラムを選んだ色で塗ったもの。実際の入力ではない）・色の流れ（-100〜0 dB のグラデーション）・特徴。

### 6.1 カード表示

- 内容: 計測の停止ボタン、デバイス名、波形ボタン、スペクトルボタン、「…」メニュー（上から「ウィンドウ表示に切り替え」「設定…」「終了」）、ch ごとのメーター（ウィンドウの半分の高さ: バー 7pt・文字 9pt。チャンネル番号・CLIP・dB 目盛りなし。クリップ中は数値を赤くする）、入力音量スライダー（ラベルなし）の順。その下に波形、スペクトルの欄。波形（ch ごとにスペクトルと同じ高さ 36pt。チャンネル番号と時間軸なし）はヘッダーの波形ボタンで表示・非表示を切り替えられ、設定は UserDefaults（`cardShowsWaveform`、既定は表示）に保存する。スペクトル（高さ 36pt）も同様にスペクトルボタンで切り替えられ、設定は `cardShowsSpectrum`（既定は表示）に保存する。スペクトルの欄はクリックでスペクトログラムと切り替えられ、どちらを表示するかは `cardShowsSpectrogram`（既定はスペクトル）に保存する。表示していないセクションは計算もしない。エラーがあれば最下段に 2 行まで表示。
- 切り替え: ウィンドウの「カード表示」ボタン、カードの「…」メニュー、表示メニュー、⌘⇧M。表示モードは UserDefaults に保存し、次回起動時も同じモードで開く（カードの「終了」で終了した場合は次回もカードで開く）。
- 実装: AppKit の `NSPanel`（`.floating`、`.nonactivatingPanel`、タイトルバーは透明で非表示）に `NSHostingView` で SwiftUI のビューを載せる。背景は `NSVisualEffectView`（`.hudWindow`、`.behindWindow`）で半透明。
  - `.nonactivatingPanel`: クリックしても前面のアプリを切り替えない。`hidesOnDeactivate = false` で他のアプリ使用中も表示し続ける。
- 移動: どこを掴んでもドラッグで移動できる（スライダーやボタンは自分の操作が優先）。標準のドラッグ移動では離した瞬間がわからないため、`isMovable = false` にして SwiftUI の `DragGesture` からマウスの画面座標で自前で動かす。
- 画面端への吸着: 離したとき、画面の表示領域（メニューバーと Dock を除く）の端から 24pt 以内なら、端から 8pt の位置に吸着する（アニメーション付き）。画面外にはみ出した場合も内側に戻す。
- サイズ: 高さは中身（ch 数など）に合わせて自動で決まり、幅だけ端をドラッグして変更できる（最小 220、既定 300）。`NSHostingView.sizingOptions = [.minSize, .maxSize]` と SwiftUI 側の `fixedSize(vertical:)` で実現する。位置と幅は `setFrameAutosaveName` で保存し、初回は画面の右上に置く。
- メインウィンドウはカード表示中も閉じずに隠す（`orderOut`）。
  - 隠すと AppKit は最後のウィンドウが閉じられたとみなすため、カード表示中は `applicationShouldTerminateAfterLastWindowClosed` で終了しない。
  - 隠したまま終了すると、次回の起動時に SwiftUI がメインウィンドウを作らないことがある。そのため起動時はメインウィンドウを待たずにカードを出し、ウィンドウに戻すときにまだ作られていなければ `openWindow` で開く。
  - Dock のアイコンをクリックしたら、カード表示中ならウィンドウ表示に戻す（カード表示中は Dock にアイコンを出さないため、通常は起きない）。
- Dock: カード表示中は `NSApp.setActivationPolicy(.accessory)` で Dock と ⌘Tab に出さない。ウィンドウ表示に戻すときに `.regular` に戻す。`.accessory` の間はメニューバーが出ないため、⌘⇧M などのメニューのショートカットは使えず、ウィンドウへの切り替え・設定・終了はカードの「…」メニューから行う。カード表示で起動したときは起動直後に切り替えるため、Dock のアイコンが一瞬見えることがある。
- 設定: カードの `NSHostingView` の中から `openSettings` を呼んでも設定ウィンドウは開かないため、Commands で受け取った `openSettings` を `DisplayModeController` に渡して使う。`.accessory` のままでは前面に出ないので、設定ウィンドウを開いている間だけ `.regular` にし（Dock にアイコンが出る）、閉じたら（`NSWindow.WillCloseMessage` で受け取る。macOS 27 からの型付きの通知で、メインスレッドで届く）カード表示中なら `.accessory` に戻す。
- 描画: メーター・波形・スペクトル・スペクトログラムの描画（`LiveMonitorView`）はウィンドウとカードで共有する。`LevelStore.read()` は読むたびに Peak の保持をリセットするため、表示していない側は描画を止める。
- 計測の開始はウィンドウとカードの両方から呼ばれるため、動作中や開始処理中なら何もしない。カード表示中もウィンドウを隠すだけなので計測は止めない。

### 6.2 iOS・iPadOS の画面

- デザインは docs/ui/ios（Claude Design のキャンバス「MicMonitor iPhone・iPad デザイン」の書き出し）。
- 画面は 1 つ（`MonitorScreen`）。ナビゲーションバーに「MicMonitor」、右に計測の停止・再開（文字付き。止めている間は主ボタン）と設定のボタン。設定はシート（`SettingsView` を NavigationStack に入れ、「完了」で閉じる）。
- 計測の欄はスクロールする。上から入力のカード（デバイスのメニューと、2 行目に「システム既定」かどうかとフォーマット。その下に入力音量の行。音量を変更できないときはその理由）と、その下の警告（フォールバック中・エラー・割り込み）、レベル、波形、スペクトログラム、スペクトル、モニター再生のカード（スイッチの行と音量の行）と注意。
- 配置は Size Class で決める（`ScreenLayout`）。
  - 高さが compact（iPhone 横）: 2 列。左に操作（入力・モニター再生）、右に計測（レベル・波形・スペクトログラム・スペクトル）。小さいタイトル
  - 幅が compact（iPhone 縦、iPad の狭い分割）: 1 列。大きいタイトル
  - regular × regular（iPad）: 横幅 1000pt 以上なら 2 列、未満なら 1 列（グラフを高く、余白を広く）
  - 文字がアクセシビリティサイズのときは 1 列にし、入力の行と欄の見出しを縦に並べる
- マイク権限が拒否されている場合は、設定アプリのこのアプリの欄を開くボタンを出す。前面に戻る（`scenePhase` が `.active`）たびに確かめ直す。
- 計測はバックグラウンドでも続ける（`UIBackgroundModes` の `audio`）。描画はバックグラウンドでは止める。
- ウィンドウは 1 つに限る（`UIApplicationSupportsMultipleScenes` を false。Info.plist の自動生成では true になるため、iOS では生成を止めて Info.plist に書いている）。`LevelStore.read()` の読み手を 1 つにするため。
- 計測の停止・再開（⌘.）は iPad のメニューバーとキーボードショートカットに出す。設定のボタンは ⌘,。
- 設定のシートは Mac の設定と同じ内容で、次の点だけ違う: 履歴の長さはラベル・秒数・ステッパーの行の下にスライダーを置き、スライダーに目盛りの点を付けない。カラーマップは「スペクトログラムのカラーマップ」の節にチェックマークの一覧で並べ、見本・色の流れ・特徴は別の節に置く。
